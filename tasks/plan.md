# Plan: Make authored gameplay and world data Inspector-editable

## Goal and scope

Let designers tune and move content without changing GDScript, while keeping the existing game, maps, visuals, collision, and performance as the default. This audit covers the gameplay scene, terrain and landmarks, actors, camera, weather, and UI/settings. It does not propose exporting every numeric literal. Implementation is not started; see [the ordered checklist](todo.md).

## Ownership and migration rules

- Use `@export` for a small number of scene-specific values, typed `.tres` for reusable profiles, and `Marker3D` / `Path3D` / instanced scenes for hand-placed composition. Keep one source of truth per value. Exporting raw dictionaries for every feature is not the goal.
- Keep collision layer meanings (terrain `1`, slime `2`, obstacles `4`), volume/clearance math, shader/CPU profile parity, shader binding names, valid state transitions, numerical epsilons, deterministic RNG steps, and performance safety caps in code. A bake-derived dimension must not become a free-standing runtime override. Keep terrain procedural noise in the vertex stage.
- Defaults must match **observed runtime behavior**, not merely declarations. Read-only Resource data must not absorb live state. Keep references to `TerrainScene`, player, HUD, and autoloads compatible while migrating one system at a time.
- Do not make terrain-critical settings live-rebuild on every Inspector drag. Use a scoped, debounced preview for visuals and explicit rebuild/rebake actions for expensive generation. Runtime world startup must not rebuild twice when presets apply.
- The prior gameplay audit (squeeze, split, merge, retry, dead-player interactions) is separate from value migration. Capture targeted baseline failures if present; fix them in explicitly scoped slices before claiming those systems are safe. Do not mask regressions by exposing a threshold.

## Verification and rollout

1. Establish baseline on the existing Docker sandbox (no local Godot run): compile and smoke output, territory actor/hazard counts, deterministic positions, terrain startup time, and matched screenshots from the Webwood trail, brood hollow, canopy, and affected regions. Capture baseline failures instead of assuming every existing check is green.
2. For each slice, verify **default parity** and a **non-default Inspector edit**. Try moving a representative marker in a test scene and verify every consumer follows; tune one profile field, reload, and prove only its intended effect changes. Run the matching gameplay tests and test a second instanced world for state isolation where relevant.
3. Keep screenshot comparisons, gameplay contracts, and benchmarks separate. Compare identical camera/time/weather conditions and preserve established scene loads, asset paths, baked collision alignment, and batched rendering. Physics and UI checks are listed with each task.

## Deliberately deferred

Region streaming, terrain collision partitioning, relocating baked caves without rebaking, and exposing arbitrary solver coefficients are **not** required for Inspector editability. Consider them only after migration parity is proven or for a separate measured performance task.
