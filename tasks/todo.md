# Inspector editability — implementation checklist

All runtime checks and renders below run in the Docker sandbox. Each task is a reviewable slice; where several files or regions are listed, apply and verify one consumer/region at a time. Default behavior must stay unchanged unless the task explicitly corrects a disconnected control. See [audit and ownership decisions](plan.md).

## 1. Establish baselines and pilot the scene split

- [x] **1. Baseline (all findings; no dependencies).** Inventory existing `.tscn` overrides, effective runtime defaults, and suspected no-op exports. Capture deterministic placements, actor/hazard totals, and representative render and startup timings. **Verify:** `test_compile_all_scripts.gd`, `test_run_main_scene.gd`, `test_cave_dungeon_territories.gd`, `test_quality_presets_and_startup.gd`, and `capture_webwood_previews.gd`; record failures without loosening tests. Files: existing `tests/` and new baseline notes only. -> Recorded in [baseline.md](baseline.md).
- [x] **2. Extract a Webwood scene without changing generation (A1/A5; after 1).** Instance it at the same point in world startup, with explicit terrain and placement inputs; retain compatible names and keep the existing generator and visual batches. **Verify:** full territory regression and matched Webwood renders. Files: `terrain/terrain.gd`, `scripts/territory_builder.gd`, new region scene and script.
- [x] **3. Make Webwood layout authoritative (A2/A5; after 2).** Migrate the origin, trail, nests, and snag anchors to local data/markers. Files: Webwood scene/profile, `territory_builder.gd`, `terrain.gd`, territory test.

**Checkpoint:** Webwood opens independently in the editor and remains seamless in the main game. Default and moved-region tests pass before reusing the pattern.
